# 검증 기록

README를 정리하면서 이전 날짜별 검사 기록을 이 문서로 옮겼습니다. 수치와 범위는 **각 검사 당시의 결과**입니다. 본문의 옛 절 번호는 당시 README 기준이며, 현재 실행법은 [개발·검증](../README.md#development)과 [실제 장치 검사](../README.md#diagnostics)를 따르세요. 실제 라파 장시간 검사와 자동 회귀 검사는 구분합니다.

### 2026-09-26 사진 전송·회전 및 전체 변경 검증

PC용 SSH/SFTP 사진 가져오기와 180도 회전 기능을 추가하고, 15부에 화면 없는 촬영부터 라벨링까지의 실행 위치·명령을 정리했습니다. 전송 테스트는 회전 픽셀 방향, 원본 보존, 폴더 구조, 중단·손상·전송 중 변경된 파일 처리, 기존 폴더 보호, 클래스 선택, EXIF 방향 정리를 확인합니다.

- Python 전체 검사: **221개 중 219개 통과, Windows 환경에서 Linux/systemd 검사 2개 제외**.
- JavaScript 화면 검사: **32개 통과**.
- Python 컴파일·패치 형식 검사 통과.
- 실제 라파 SSH/SFTP 연결로 기존 사진 3장 복사·180도 회전 확인. 실제 카메라 재촬영이나 YOLO 학습을 실행한 검사는 아닙니다.
- GitHub 자동 검사에서도 `requirements-photo-transfer.txt`를 설치해 사진 전송 테스트를 실행합니다.

### 2026-09-26 전체 코드 리팩토링·자원 점검

촬영 기능뿐 아니라 로그인·권한, 대여·반납, SQLite, 객체인식, 웹 화면, 서버 종료·배포 도구, Colab 노트북까지 검토했습니다. 모델 로딩 실패 시 남는 이미지 참조, 중단된 DB 작업의 롤백 누락, LED·부저 오류가 저장 성공을 실패로 바꾸는 문제, 화면 이탈 시 요청·타이머 정리 등을 추가 수정했습니다. Colab 사진 검증도 결과 전체를 보관하지 않는 스트리밍 방식으로 변경했습니다.

Windows PC에서 Python 213개 중 211개 통과·2개 건너뜀, JavaScript 32개 통과를 확인했습니다. 대여·반납 500쌍의 반복 검사와 1080p 합성 이미지 미리보기 1,000회 검사도 수행했습니다. 실제 Pi의 카메라·YOLO 장시간 안정성 검사를 대신하지는 않습니다.

상세한 점검 범위, 수정 이유, 메모리 측정값과 재실행 명령은 [전체 코드 점검 결과](REFACTORING_AUDIT_2026-09-26.md)에 정리했습니다. `.env`나 운영 DB를 새로 만들 필요는 없습니다.

### 2026-09-26 촬영 미리보기 리팩토링·메모리 점검

수동 촬영과 브라우저 미리보기에서 중복되던 최신 프레임 선택·USB 대기 프레임 버리기·반복자 종료를 `fresh_frame()`으로 통합했습니다. 이미지 변환 후 반복자 정리에 실패하면 오류 기록에 JPEG 버퍼가 남던 경로를 재현하고 수정했습니다. 미리보기 오류 로그에는 예외 객체 대신 문자열만 전달해 버퍼를 간접 참조하지 않도록 했습니다.

브라우저에서 페이지를 떠났다가 돌아올 때 대기 중이던 촬영 클릭이 재실행되는 문제를 수정했습니다. 탭 숨김·페이지 이동 시 화면 이미지와 미리보기 요청·타이머를 정리하고, 늦게 도착한 이전 화면은 폐기합니다. 이미 전송된 저장 요청은 탭을 숨겼다는 이유만으로 취소하지 않으며, 연결이 끊겨도 자동 재촬영하지 않습니다. 복귀 후 새 화면 응답으로 실제 저장 장수를 다시 확인합니다.

Windows PC에서 1920×1080 모의 이미지를 만들고 **실제 OpenCV JPEG 변환 및 파일 저장**을 수행했습니다. 100회 예열 후 미리보기 1,000회 동안 RSS는 **68.7MB → 68.7MB**였고, 예열을 포함해 44장의 임시 사진을 저장했습니다. 이전 프레임·앱 참조가 해제됐고 Python 스레드 수는 1개로 유지됐습니다. 브라우저 검사에는 500회 화면 갱신과 100회 페이지 복귀 반복이 포함됩니다. 이는 실제 Raspberry Pi 센서·YOLO 추론이나 모든 조건에서의 누수 부재를 보장하는 결과는 아닙니다.

> **실행 위치: Windows PC PowerShell의 프로젝트 폴더 — OpenCV와 NumPy가 설치된 환경에서 선택 실행. 운영 사진·DB 대신 임시 폴더를 사용합니다.**

```powershell
python tests/test_capture_preview_soak.py --cycles 1000 --warmup 100
```

OpenCV/NumPy가 없는 환경에서는 일반 자동 테스트 중 이 JPEG 검사 하나만 건너뜁니다. 모의 카메라·프레임 참조·브라우저 자원 정리 검사는 계속 실행됩니다.

별도의 임시 DB 검사에서는 100쌍 예열 후 대여·반납 500쌍을 반복했습니다. RSS는 47.4MB → 48.8MB였고, 중간 측정값은 48.6 / 48.7 / 48.8 / 48.7 / 48.8MB였습니다. DB 무결성, 미반납 수량 0, 종료 후 앱·로그 핸들러 해제를 확인했습니다.

### 2026-09-18 리팩토링·자원 정리 점검

카메라 프레임 반복자의 종료 처리를 공통 함수로 모았습니다. 특히 점검 중 반복자 종료가 중단되었을 때 오류 정보에 이미지 참조가 남던 경로를 수정했습니다. 이전 코드에서 이미지 참조가 남는 것을 재현한 뒤, 수정 코드에서 640×480×3바이트 모의 프레임과 중단 오류를 100회 반복하며 이미지가 해제되는지 확인합니다. 실제 카메라 드라이버나 YOLO 내부의 모든 참조가 해제된다는 보장은 아닙니다.

대여·반납, 거래 취소·삭제, 기자재 삭제·일괄 변경의 DB 쓰기 잠금과 롤백 처리는 `db.immediate_transaction()`으로 통일했습니다. 일반 오류뿐 아니라 `KeyboardInterrupt`·`SystemExit`와 저장 확정 실패에도 부분 변경과 열린 트랜잭션이 남지 않도록 검사합니다. 서버 종료 도중 다시 중단 신호가 들어와도 나머지 서비스 정리를 시도한 뒤 중단을 전달합니다.

미반납 목록은 학생·기자재 조합 100개씩 이전/다음 페이지로 이동합니다. 상단의 미반납 수량과 연체 학생 수는 현재 페이지가 아닌 전체 기록 기준입니다. 백그라운드 정리 작업은 서로 독립된 DB 연결 수명으로 실행해 한 작업이 실패해도 나머지 정리를 시도합니다.

Windows PC에서 임시 DB와 모의 인식기로 100쌍을 예열한 뒤 대여·반납 500쌍, 관리자 화면·CSV·현황 조회를 각각 500회 반복했습니다. 예열 후 RSS 47.9MB, 측정 구간 48.7 / 48.8 / 48.9 / 48.9 / 48.9MB였습니다. 예열 포함 거래 1,200건의 DB 무결성을 확인했고, 스레드는 1개로 유지됐으며 종료 후 앱 참조와 추가 로그 핸들러가 해제됐습니다. 이 수치는 해당 PC의 웹 처리 경로 측정으로, Pi의 실제 YOLO 장시간 추론이나 모든 메모리 누수의 부재를 보장하지 않습니다.

같은 웹 반복 점검을 다시 실행하려면 다음 명령을 사용합니다. `.env`를 불러오지 않고 임시 DB와 모의 인식기만 사용하며, 운영 DB·카메라·GPIO는 사용하지 않습니다. 결과의 RSS는 관찰값이며 자동으로 누수 없음 판정을 내리지 않습니다.

> **실행 위치: Windows PC의 PowerShell, 프로젝트 폴더에서 가상환경 활성화 후**

```powershell
python tests/test_resource_soak.py --cycles 500 --warmup 100
```

실제 Pi 카메라·모델은 9부의 `scripts/memory_soak_test.py`로 별도 확인합니다. 코드 업데이트를 위해 `.env`나 기존 DB를 새로 만들 필요는 없습니다.

### 이전 점검 기록

2026-09-14에는 USB 카메라가 다음 프레임을 읽기 전에 이전 이미지 참조를 해제하도록 보완했습니다. Picamera2 정지나 YOLO 결과 스트림 종료 도중 중단이 발생해도 남은 장치·이미지 정리를 실행합니다. 학습 사진 수집은 촬영·파일 저장·자원 종료 함수를 분리했고, 저장 실패·출력 오류·`Ctrl+C`에도 촬영 반복자를 먼저 닫고 카메라를 닫습니다. 중단된 촬영은 성공 대신 종료 코드 130을 반환하며, 이미 저장된 사진은 유지합니다.

Windows PC에서 640×480×3바이트 모의 이미지로 10회 예열 후 USB 촬영 경로를 1,000회 반복한 결과, Python 추적 최대 할당량은 수정 전 1,844,378바이트에서 수정 후 924,993바이트로 줄었습니다. 이는 이전·다음 프레임이 겹쳐 보관되는 양을 줄인 결과이지, 전체 서버 RSS가 절반이 되거나 모든 누수가 없어졌다는 뜻은 아닙니다. 별도 회귀 검사에서는 사진 수집 100회 동안 이전 이미지 참조가 해제되는지도 확인합니다. 실제 Pi 카메라·OpenCV·YOLO의 네이티브 메모리는 모델 적용 후 장시간 검사해야 합니다.

2026-09-10에는 인식 후 통계 처리·메모리 정리에서 오류가 나도 인식 잠금이 반드시 해제되도록 구조를 분리했습니다. 진단 스크립트도 예열 중 `Ctrl+C`, 예외, 출력 오류를 포함한 모든 실행 경로에서 종료 처리를 거치도록 정리했습니다. 메모리 검사는 측정 구간의 인식 성공이 0회이면 RSS가 일정해도 실패로 판정합니다.

회귀 검사에는 정리 오류를 주입한 인식 100회 반복과, 진단 예열 중 중단을 20회 반복하며 실제 앱의 로그 핸들러·인식 서비스·앱 참조가 해제되는지 확인하는 검사가 포함됩니다. 오류 주입과 모의 인식기를 사용하는 검사이며, 실제 Pi의 메모리 고갈이나 카메라·YOLO 장시간 실행을 검증한 것은 아닙니다.

자원 정리 검사에는 초기화 실패 시 로그 핸들러·DB 연결 해제, USB 카메라 설정·예열 실패 시 장치 해제, 지연된 백그라운드 작업의 종료, 긴 오류 로그의 용량 제한이 포함됩니다.

종료 중 늦게 완료된 요청이 GPIO 표시기와 작업 스레드를 다시 생성하지 못하도록 생성·종료 상태를 같은 잠금으로 보호합니다. GPIO 큐·스레드 객체도 장치를 열기 전에 준비해 메모리 할당 실패 시 열린 장치가 남지 않도록 했습니다. 대여 사유 검증은 별도 함수로 정리했고 200자 초과 입력은 UTF-8 복사 전에 거절합니다. 화면의 인식 결과 초기화 코드와 날짜 포맷 객체도 재사용합니다.

2026-09-09 Windows PC의 모의 인식 환경에서 250쌍 예열 후 대여·반납 500쌍(1,000건), 관리자 화면·CSV 조회 각 500회를 반복했습니다. 예열 후 RSS는 49.8MB였고, 100쌍마다 측정한 값은 49.5 / 49.5 / 49.8 / 48.6 / 49.6MB였습니다. 스레드는 1개로 유지됐고 종료 후 앱 로그 핸들러는 0개였습니다. 임시 DB를 사용한 웹 처리 경로의 측정이므로 실제 Pi 카메라·YOLO 메모리 검사나 모든 실행 조건의 누수 부재를 보장하지 않습니다.

수동 배포 서버의 실행·종료 관리는 `equipment_manager/web_server.py`로 분리했습니다. 포트 충돌로 시작에 실패하거나 서버 루프가 종료돼도 작업 스레드와 소켓을 정리합니다. 관련 처리는 [Waitress 서버 구현](https://github.com/Pylons/waitress/blob/main/src/waitress/server.py)을 기준으로 검사합니다. GPIO 작업 스레드 시작 실패, GPIO 끄기 오류, Picamera2 예열 중 `Ctrl+C`가 발생했을 때도 열린 장치를 닫도록 보완했습니다.

2026-09-08 Windows PC에서 120회 예열 후 포트 충돌에 의한 시작 실패를 1,000회 반복했습니다. 수정 후 RSS는 45.3MB → 45.3MB, 스레드 수는 1개 → 1개였고, GC 후 Python 추적 메모리 증가량은 1,579바이트였습니다. 회귀 검사에서는 실패 후 소켓 관리 항목이 비고 앱 참조도 해제되는지 확인합니다. 이 측정은 포트 충돌·정리 경로에 한정되며 실제 Raspberry Pi의 장시간 YOLO 추론 결과나 메모리 누수 부재를 보장하지 않습니다.

2026-09-06 Windows PC의 모의 인식 모드에서 30회 예열 후 대여·반납 200쌍(400건)과 로그 조회·삭제 200회를 반복했습니다. RSS는 47.3MB에서 47.8MB로 증가한 뒤 유지됐고, 종료 후 앱 로그 핸들러는 0개였습니다. 이 결과는 웹 처리 경로의 측정이며 실제 Raspberry Pi의 YOLO·카메라 메모리 검사를 대체하지 않습니다.

최종 버튼 중복 제출 방지, 인식 만료 카운트다운, 요청 시간 초과·페이지 이동 시 정리도 확인할 수 있습니다. Node.js가 설치된 PC에서 실행합니다. Raspberry Pi 서버 실행을 위해 Node.js를 설치할 필요는 없습니다.
