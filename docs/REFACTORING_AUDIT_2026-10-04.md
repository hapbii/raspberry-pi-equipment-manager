# 전체 코드 리팩토링·메모리 점검 — 2026-10-04

서버·DB·계정·대여/반납·카메라·추론·GPIO·브라우저·운영 도구를 점검했습니다. 이미 있는 자원 정리 구조는 유지하고 재현한 오류 경로를 수정했습니다. 검사는 Windows PC에서 수행했으며, 이번 리팩토링 작업 중 라파에 SSH로 접속하거나 배포하지 않았습니다. 운영 `.env`, DB와 원본 모델을 변경하지 않았습니다.

## 수정 내용

1. **보관된 오류가 이미지 버퍼를 붙잡는 문제**: 호출자에서 `frame = None`으로 지워도 모델·카메라 라이브러리 내부의 오류 프레임에 이미지가 남았습니다. 공통 `release_error_frames()`로 종료된 호출 프레임의 지역 변수 참조를 해제합니다. 원인 연결과 파일·함수·줄 번호·오류 메시지는 보존하며 실행 중인 프레임은 지우지 않습니다. 추론, 카메라, 미리보기 JPEG 변환, 촬영 저장과 반복자 종료에 적용했습니다.
2. **CPU 실행 설정 분리**: 모델 준비를 `vision/inference_runtime.py`로 분리했습니다. Ultralytics가 CPU 선택 중 Torch 스레드 수를 바꾼 뒤 `INFERENCE_THREADS`를 다시 적용합니다. NCNN은 설정한 스레드 수로 해당 네트워크를 로딩한 후 초기 네트워크를 해제하고 재사용합니다. 전역 `ncnn.Net`을 수정하지 않습니다. 새 네트워크 로딩 실패 시 새 자원을 해제합니다.
3. **중단 중 GPIO 정리**: worker 종료 대기나 장치 끄기가 `KeyboardInterrupt`로 중단돼도 대기 이벤트와 모든 GPIO 장치의 정리를 시도한 뒤 중단을 전달합니다.
4. **현황 화면 타이머 정리**: 화면 이탈·탭 숨김 시 진행 중 요청뿐 아니라 요청 제한 타이머도 즉시 해제합니다. 지연 응답과 100회 페이지 복원에서도 요청을 중복 실행하지 않습니다.
5. **메모리 측정 도구의 반복 할당 축소**: Windows RSS 조회의 ctypes 구조체·포인터·API 바인딩을 한 번 준비해 재사용합니다. 모델 비교 도구는 50ms마다 관측한 전체 RSS·온도 목록을 쌓는 대신 최대값·첫값·마지막값만 유지합니다.
6. **학습·비교 코드와 문서 보관**: 앞서 작성한 NCNN 변환·PT/NCNN 비교 도구를 포함합니다. README의 학습 완료 상태, 현재 IP와 회전 없는 사진 전송 예시를 갱신하고 [모델 비교 안내](../training/MODEL_COMPARISON.md)를 추가했습니다. 이전 라파 속도 측정의 저전압 제한도 기록합니다.

계정·CSRF·SQLite 트랜잭션·페이지 조회 제한·로그 크기 제한·서비스 종료·업데이트 처리도 기존 자동 검사와 코드 검토로 확인했습니다. 업무 동작을 바꾸기 위한 전면 재작성이나 DB 이관은 수행하지 않았습니다.

## 재현 및 회귀 검사

추론 오류 100개와 카메라 읽기 오류 100개를 보관한 조건에서 각각 640×480×3바이트 이미지가 해제되지 않는 것을 수정 전에 재현했습니다. 수정 후에는 모든 이미지의 weak reference가 해제됐습니다. JPEG 인코더 오류 100개 보관, 중단된 GPIO 정리, NCNN 로딩 전 스레드 설정·실패 정리, Windows API 바인딩 재사용과 페이지 이탈 즉시 타이머 해제도 검사합니다.

- Python: **243개 중 240개 통과, 3개 건너뜀**. 이 수치는 Windows 환경의 결과이며 운영체제·설치된 선택 패키지에 따라 건너뛰는 항목이 달라집니다.
- JavaScript: **34개 모두 통과**.
- Python 컴파일 및 `git diff --check`: 통과.

PT·NCNN 검사에서는 실제 카메라 대신 로컬 검증 JPG를 새로 디코딩해 입력했습니다. 입력 320, 신뢰도 0.60, 프레임 1, 투표 1로 반복 자원 정리를 검사했고 PT는 비교를 위해 정사각형 입력을 사용했습니다. 각 모델에서 성공 267회·검출 없음 33회였으며, 오류 33개를 보관한 상태에서도 이미지 참조가 해제됐습니다. Torch 스레드 2와 NCNN 네이티브 스레드 2를 확인했습니다. NCNN 초기 네트워크를 교체한 후 추가 네트워크를 매번 만들지 않았고 종료 후 모델도 해제됐습니다.

검사에는 Ultralytics 8.4.164, PC Torch 2.13.0+cpu와 NCNN 1.0.20260526을 사용했습니다. 예열 직후와 다른 물체를 포함한 반복 구간의 RSS 차이는 캐시·메모리 할당을 포함할 수 있습니다. 수치만으로 누수의 유무를 단정하지 않고 반복 추이와 참조 해제를 함께 확인했습니다.
