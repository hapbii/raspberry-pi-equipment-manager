# 리팩토링·디버깅·메모리 통합 점검 — 2026-10-12

이전 리팩토링과 [같은 날짜의 디버깅 수정](DEBUGGING_AUDIT_2026-10-12.md)은 유지했습니다. 이번에는 인식 서비스의 작업 경계·통계 처리, 백그라운드 오류 기록, 메모리 검사 도구를 추가로 정리했습니다. 수정과 검증은 PC 작업 폴더에서 수행했습니다.

## 추가 수정

| 파일 | 변경 |
|---|---|
| `vision/service.py` | 인식·사전 점검의 중복된 잠금·종료 상태 확인·오류 프레임 해제를 `_operation()`으로 통합했습니다. 성공·실패 집계와 주기적인 GC를 `_finish_attempt()`로 분리했습니다. 최종 시간 측정 실패가 원래 인식 오류를 가리거나 정상 결과를 버리지 않도록 했고, 시작 시간 측정 실패도 실패 횟수에 집계합니다. 상태 시각을 기록할 수 없을 때는 경고를 남기고 시각을 `None`으로 표시하며 실제 인식 결과를 유지합니다. |
| `runtime.py` | 백그라운드 작업·RSS 조회 오류를 기록하기 전에 완료된 오류 프레임을 해제합니다. 정리 작업이 끝나면 유지보수 프레임의 앱 참조도 제거합니다. 원시 예외 정보를 보관하는 로그 핸들러가 있어도 실패한 작업의 임시 버퍼와 폐기한 앱이 남지 않도록 했습니다. 각 작업의 독립된 DB 문맥과 다음 작업 실행은 유지합니다. |
| `scripts/memory_soak_test.py` | 검사 횟수·대기 시간·RSS 증가량 기준의 공통 검증을 추가했습니다. 횟수는 양의 정수, 시간과 기준은 유한한 0 이상의 값이어야 합니다. `NaN`·무한대·음수 등 잘못된 옵션을 거절해 의미 없는 검사·통과 판정을 방지합니다. CLI에서는 앱 생성 전에 거절하고, 이미 생성된 앱으로 함수를 호출한 경우에도 종료 정리를 실행합니다. |

추가 회귀 검사 7개는 수정 전 실패했고 수정 후 통과했습니다. 유지보수 오류 100회에서는 원시 `LogRecord.exc_info`를 계속 보관한 상태에서도 합성 버퍼 100개와 앱 100개의 약한 참조가 모두 해제됐습니다. 오류 후 다음 작업 200회 실행과 Flask 문맥 해제도 확인했습니다. 실제 장치가 아닌 오류 주입 검사입니다.
