# 시스템 화면의 YOLO / mock 전환

개발자 시스템 화면의 버튼으로 인식 서비스만 교체합니다. 웹서버와 로그인은 유지하며 인식·점검·거래와 같은 잠금을 사용합니다. 처리 중이거나 다른 요청에서 모드를 바꾼 경우 거절합니다.

`.env`의 `DETECTOR_MODE`와 `ALLOW_MOCK_MODE`를 비공개 임시 파일에 함께 기록하고 원자적으로 교체합니다. 쓰기 실패 시 기존 서비스와 설정을 유지하며 사용하지 않은 새 인식기를 닫습니다. 기존 인식기는 교체 후 닫아 카메라·모델 참조를 해제합니다. YOLO 모델 경로를 확인하되 실제 카메라 접근과 모델 로딩은 다음 점검·인식 시 수행합니다.

mock은 웹 확인용이며 실제 인식과 거래를 거절합니다. 이전 인식 토큰을 보내거나 모드 검사와 거래 사이에서 전환을 시도하는 경우도 검사합니다. `ALLOW_MOCK_MODE=true`는 재시작 후 mock 시작의 명시적 허용값이며 계정·CSRF·YOLO 모델 검사를 생략하지 않습니다.

## PC 검증

- Python 280개 중 277개 통과, Windows에서 Linux/systemd 검사 3개 제외.
- JavaScript 37개 통과. Python 3.11 문법 검사 83개 파일 및 `git diff --check` 통과.
- 권한·CSRF, 왕복 전환, 인식 중 거절, 중복 요청, 모델 없음, 설정 저장 실패, 외부 설정 변경, 기존 토큰의 mock 거래 거절, 거래 중 전환 거절 검사.
- 20회 교체한 이전 인식기의 약한 참조 해제 확인.
- 실제 브라우저에서 CSRF 폼으로 mock → YOLO → mock 왕복, 상태 응답, mock 인식 거절과 모바일 배치 확인. 임시 DB와 빈 모델 경로 확인용 파일을 사용했으며 실제 카메라는 사용하지 않음.

운영 라파에 반영한 뒤에는 웹 버튼 왕복과 재시작 후 유지, 최종 YOLO 복구를 별도 확인합니다. 실제 물품 인식 성공과 장시간 운영 검사는 이 PC 검증에 포함하지 않습니다.
